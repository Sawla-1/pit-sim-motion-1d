React Hooks Usage in Physics Simulation - Discussion Summary
============================================================

1. useEffect - Animation Loop Management
----------------------------------------
Purpose: Turn on/off requestAnimationFrame loop

Usage: 
useEffect(() => {
  let raf = requestAnimationFrame(loop)
  return () => cancelAnimationFrame(raf)
}, [simulation.playing, onStep])

Why useEffect:
- Manages side effects (animation loop)
- Responds to state changes (play/pause)
- Provides cleanup when component unmounts
- Single responsibility: animation lifecycle

Dependencies:
- simulation.playing: Start/stop animation when play state changes
- onStep: Restart animation if physics function changes

2. requestAnimationFrame vs useFrame
------------------------------------
Choice: requestAnimationFrame (NOT useFrame)

Why requestAnimationFrame:
- Fixed timestep physics: Consistent 24 FPS regardless of display frame rate
- Frame accumulation: Smooth physics with frame accumulation
- Precise control: Full control over when physics runs
- Smooth graphs: Produces straight, consistent graph lines

Why NOT useFrame:
- Variable timestep: Runs at display frame rate (30-120 FPS, inconsistent)
- No frame accumulation: Can't accumulate frames for smooth physics
- Limited control: React Three Fiber controls timing
- Jagged graphs: Produces wavy, inconsistent graph lines

Result: Professional-quality physics simulation with smooth, accurate graphs

3. useRef - Persistent Values Without Re-renders
------------------------------------------------
Total useRef variables: 2

3.1 last ref
const last = useRef(performance.now())
Purpose: Animation timing for physics simulation
- Stores timestamp of last animation frame
- Used for calculating frame time differences
- Why useRef: Updates every frame (60+ times/second) - would cause massive re-renders with useState

3.2 chartRefs ref
const chartRefs = useRef([])
Purpose: Store references to Chart.js chart instances
- Array of chart objects for drag functionality
- Used for timeline scrubbing on charts
- Why useRef: DOM references that don't need to trigger re-renders when updated

Key Principles
--------------
1. Single Responsibility: Each hook has one clear purpose
2. Performance: useRef for values that don't need re-renders
3. Side Effects: useEffect for animation lifecycle management
4. Physics Accuracy: Fixed timestep for consistent, professional results

Architecture Benefits
--------------------
- Clean Code: Each hook serves a specific, well-defined purpose
- Performance: Optimized to prevent unnecessary re-renders
- Maintainability: Easy to understand and debug
- Professional Quality: Physics simulation follows industry standards

This architecture ensures our physics simulation runs smoothly, accurately, and efficiently while maintaining clean, readable code.
